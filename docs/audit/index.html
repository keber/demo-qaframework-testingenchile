Threshold objections

D2.systemic-assertless (no se objeta el límite del 5%, sino la medición que lo alimenta): los 32 tests contados como assertless son tests omitidos en ejecución mediante skipPending(), helper de qa/07-automation/e2e/fixtures/pending.ts que llama a test.skip(true, motivo). El extractor no reconoce test.skip envuelto en un helper, de modo que D2.assertless-tests sobrestima (25% en vez de 0%) y D2.skipped-tests / D5.skip-ratio subestiman (0% en vez de 25%). El nivel 0 se mantendría igual bajo la lectura correcta, porque un 25% de tests omitidos tampoco puede fallar, pero el motivo reportado es otro.

D2.expected-failures: 9 tests usan expectOpenDefect() (qa/07-automation/e2e/fixtures/defects.ts), que llama a test.fail en tiempo de ejecución para defectos abiertos; el extractor solo cuenta test.fail declarado y reporta 0.

D3.fixed-waits: la única espera fija detectada (detalle-curso.spec.ts:33) es test.setTimeout(...), que fija el presupuesto de tiempo del test y no es una espera.

D6.runs-the-suite: el job e2e de .github/workflows/qa.yml ejecuta npm test (-> playwright test) con working-directory ${{ env.E2E_DIR }}, y E2E_DIR vale qa/07-automation/e2e en el bloque env del propio workflow. El extractor no resuelve el directorio pasado por variable y determina 0; con la resolución correcta el nivel 1 sería alcanzable (corre en CI, solo manual y semanal, sin bloquear el merge).
